--------------------------------------------------------------------------------
INITIAL PROMPT (Interactive / Pairing)
--------------------------------------------------------------------------------

I have this problem where I'm using Tailscale as a relay to advertise this subnet I have on my machine to other machines, which aren't running the client yet. When I start Tailscale, the route metric to the subnet on the main interface gets increased, resulting in losing connection to the whole subnet because now all the traffic is flowing through Tailscale. This seems to be a problem because the ACLs only allow relaying to a few machines. My expectation is that routes should not be set if there is an existing interface with an IP which gives direct access to that subnet.


--------------------------------------------------------------------------------
HIGH-LEVEL TASK GOAL
--------------------------------------------------------------------------------

As entered in Studio: Ensure that routes are not set when there is an existing interface with an IP that gives direct access to the subnet, bypassing Tailscale's subnet relay.

The goal of the task is to find out why tailscaled programs an operating-system route for a subnet that the machine can already reach directly through one of its own NICs, so that LAN traffic is pulled into the tunnel and then dropped by ACLs that only allow relaying to a few machines, and to change the engine so that route is not installed in that situation. The difficulty is that the environment is never stated. One router.Config goes to three unrelated OS implementations (Linux policy routing, Windows interface routes and metrics, macOS/BSD route(8)) and only one of them can express "do not route this" today. The route set is built in one place but interface state changes arrive somewhere else. The exit-node code path deliberately adds local subnets to the tunnel. And the obvious rule ("skip it when any NIC covers it") opens a gap on a foreign network that happens to reuse the same prefix. Success looks like a fix that is placed and scoped deliberately, keeps working when interfaces come and go, leaves supernets, exit routes and the exit-node LAN protections alone, is verified honestly per platform (ran versus compiled versus read), and names the residual risk instead of declaring the problem closed.
